# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

3D Previewer — локальное веб-приложение для просмотра и проверки `.glb`-моделей игры ПВЗ (Godot) перед импортом. Интерфейс, сообщения, комментарии в коде — на русском; так и продолжать.

## Команды

- `npm run dev` — сервер (`tsx watch`) + Vite с HMR, открывать http://127.0.0.1:4311 (Vite проксирует `/api` и WebSocket на порт сервера из `3d-previewer.config.json`). Аргументы уходят серверу: `npm run dev -- --models-dir <путь>`.
- `npm start` — сборка фронта в `web/dist/` и сервер на http://127.0.0.1:4310.
- `npm run typecheck` — единственная автоматическая проверка. Тестов и линтера в проекте нет.
- `npm run fetch:hdri` — разово скачать HDRI для пресетов света (`web/public/hdri/`, в git не лежат).
- Декодеры Draco/Basis копируются из `three` в `web/public/decoders/` скриптом `scripts/copy-decoders.ts` (postinstall, dev, build) — вьювер не ходит в интернет.

Папка моделей: `--models-dir` → `MODELS_DIR` → `modelsDir` в `3d-previewer.config.json` (файл в `.gitignore`, создаётся при первом запуске). `models/` в корне — симлинк на `../models` (общая библиотека PVZ).

## Архитектура

Три части с общими типами API в `shared/types.ts` (импорты с явным расширением `.ts`, запуск через `tsx` без сборки сервера).

**Сервер (`server/`, Fastify).** `ModelLibrary` (`scanner.ts`) обходит папку моделей через chokidar (с `awaitWriteFinish` — Blender пишет файлы не атомарно), считает sha1 каждого `.glb` и ставит его в последовательную очередь анализа. Приложение **никогда не пишет в папку моделей** — весь кеш в `.cache/`.

- Анализ идёт в отдельном worker-потоке (`analyze/pool.ts`), вход — `worker-entry.mjs`, который регистрирует tsx внутри потока (иначе `.ts` не загрузится). Зависший поток перезапускается по таймауту.
- Результат `analyzeGlb` кешируется по хешу содержимого в `.cache/analysis/<sha1>-v<ANALYZER_VERSION>.json`. **При любом изменении логики анализа или проверок по содержимому увеличивать `ANALYZER_VERSION`** в `server/analyze/index.ts`, иначе останется старый кеш.
- Проверки (коды E/W/I из раздела 6 ТЗ) разделены: `validate/file.ts` — по сырому JSON и gltf-validator (работают даже на битом файле), `validate/model.ts` — по документу gltf-transform; обе кешируются с анализом. Проверки, зависящие от соседних файлов (E1, W11, I5 — `environmentIssues`), считаются в сканере на лету и в кеш не попадают. Одна `Issue` на код; затронутые объекты/материалы/текстуры — в `targets[]`.
- ID модели — POSIX-путь к `.glb` относительно папки моделей; проверка в `resolveModelId` (`server/index.ts`).
- `.blend` привязывается к `.glb` по совпадению имени в той же папке; правило «единственный .blend в папке» — только если и `.glb` в папке один. Custom Property `placement: wall` (из glTF extras, `analyze/meta.ts`) отключает W6 «не стоит на полу». Теги модели — тоже из Blender extras.
- Изменения каталога рассылаются по WebSocket `/api/events` (`ServerEvent`); клиент после переподключения перезагружает данные целиком.

**Миниатюры** рендерит браузер, а не сервер: очередь `web/src/thumbs/queue.ts` (видимые карточки первыми) → `ThumbRenderer` → `PUT /api/thumbs/:hash` (WebP, PNG как запасной вариант для Safari) → сервер хранит в `.cache` и шлёт событие `thumb`.

**Фронт (`web/src/`, React 19 + react-three-fiber + zustand, react-router).** Страницы: каталог `/`, инспектор одной модели `/view?…`, сцена из нескольких моделей `/scene/:id`, настройки `/settings`.

- Состояние — zustand-сторы в `store/`. Настройки вьювера в localStorage через `store/persist.ts` (префикс `3d-previewer.`). Режим отображения, влажность и вращение намеренно **не** сохраняются; манекен/габариты/тени — сохраняются.
- Сцены хранятся только в localStorage браузера (`store/sceneLibrary.ts`: ключ `3d-previewer.scene.<id>` на сцену, без общего индекса, автосохранение). Сохранённые сцены ссылаются на ID моделей — при переносе моделей в другие папки дописывать соответствие в `store/modelPathMigration.ts`.
- Связь «объект из анализа ↔ объект three.js» — по индексу узла glTF через `parser.associations` (`three/objects.ts`). Скрытие объектов и режим «только каркас» сделаны слоями three.js (30 — скрытые, 31 — только каркас; `three/wireframe.ts`), а не `visible` — учитывать при рейкастах и рендере.
- Свет пресетов общий для вьювера и миниатюр (`three/presetLights.ts`).
- Сцена (`three/sceneStage.ts`): один загруженный образец `.glb` на версию модели + clone-копии с общими ресурсами. В UI координаты показываются в осях Blender (Z вверх, `three/blenderAxes.ts`); привязка гизмо 10 см / 15° считается вручную.
- Горячие клавиши — `useViewerHotkeys.ts` / `useSceneHotkeys.ts`; `isTyping` не считает чекбоксы и ползунки вводом текста.

## Как работать с пользователем

- Пользователь — автор моделей в Blender; мыслит осями Blender и игровыми папками.
- Новые крупные функции делаются по этапам: после каждого этапа — короткая инструкция для проверки (команда, URL, что смотреть) и остановка до подтверждения.
- Цвет и прозрачность линий каркаса намеренно зашиты, настраиваемыми не делать.
